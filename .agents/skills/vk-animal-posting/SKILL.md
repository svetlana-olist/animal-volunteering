# Размещение объявлений ВКонтакте

Выполняй задачу как последовательность состояний: **подготовлено → группа допустима → форма проверена → отправлено → результат проверен → отчёт записан**. Не переходи к следующему состоянию по факту клика: переход подтверждается наблюдаемым результатом в файлах или интерфейсе.

Для браузерной работы используй только `npm run vk -- ...`. Не пиши временный JS-файл для конкретного животного, не вызывай `chromium.launch()` и не создавай новый browser context на каждом шаге. CLI запускает один Edge с постоянным профилем, подключается к нему через CDP и хранит этап операции в `.tmp-vk-post-state.json`.

По команде пользователя «разместить объявления» сначала подготовь карточку и выбери допустимую группу по правилам ниже. Затем запусти `npm run vk -- session`. **Первым браузерным действием должна быть проверка авторизации этой командой.** До подтверждения авторизации не открывай группу, форму и не загружай файлы. Если команда возвращает `login_required`, оставь Edge открытым, передай управление пользователю и дождись, пока он самостоятельно войдет. Не вводи, не запрашивай и не сохраняй логин, пароль, коды подтверждения или CAPTCHA. После действий пользователя снова выполни `npm run vk -- session`.

При управлении VK через Playwright обязательно прочитай [references/playwright-workflow.md](references/playwright-workflow.md). Там описаны варианты текущего интерфейса, устойчивые селекторы, проверки текста и вложений, а также безопасные остановки.

Перед размещением:

1. Найди выбранное животное ровно в одной папке `animals/dogs/<имя>` или `animals/cats/<имя>`. Не используй `archive`.
2. Прочитай `info.md`. Если файла нет или устойчивые внешние признаки нельзя уверенно сопоставить с медиа, остановись без отправки.
3. Прочитай `advertisement.md` как единый текст. Он должен быть непустым; не редактируй, не сокращай и не дополняй его при размещении.
4. Собери медиа только из папки этого животного. Каждый файл обязан начинаться с `<имя>-`; визуально проверь, что на всех фотографиях и видео именно животное из `info.md`.
5. Прочитай `VkGroups.md` и весь `REPORT.MD`, затем построй список допустимых групп. Для каждой группы отдельно проверь вид животного, пометки «ПЛАТНО»/«пропустить», 7-дневный интервал для текущего животного и интервал 1,2 дня между любыми нашими объявлениями.
6. Если пользователь не указал группу, выбирай случайно среди допустимых, а при неудаче переходи по случайно перемешанному списку. Не выбирай «первую по файлу» или по алфавиту.
7. На странице выбранной группы до открытия формы проверь доступность, наличие способа создать/предложить пост и ссылку «Предложенные N». Если среди предложенных уже есть наше объявление, пропусти группу.

После визуальной проверки всех медиа создай неизменяемый план:

```powershell
npm run vk -- prepare --animal "<имя>" --group-url "<url>" --media-reviewed
```

Команда должна завершиться успешно. Она проверяет единственность карточки, обязательные файлы, префиксы медиа, наличие группы в `VkGroups.md`, тематику, 7-дневный интервал, интервал 1,2 дня и чередование животных. Не обходи ошибку CLI ручным браузерным скриптом: исправь входные данные или выбери другую допустимую группу.

## Обязательная последовательность CLI

Выполняй ровно по одному шагу и читай JSON-ответ перед следующим:

1. `npm run vk -- prepare --animal "<имя>" --group-url "<url>" --media-reviewed`
2. `npm run vk -- session`
3. `npm run vk -- open-group`
4. Проверь раздел предложенных по возвращённому `suggestedHref`. CLI всегда открывает этот раздел напрямую, даже если VK скрыл ссылку, и блокирует продолжение, если текст любой записи совпал с `advertisement.md` активной карточки.
5. `npm run vk -- fill --suggested-reviewed`
6. Проверь в ответе `count`, `textVerified` и сохрани выданный `reviewToken`.
7. `npm run vk -- publish --token <reviewToken>`
8. Если результат не подтвержден, выполняй только `npm run vk -- verify`. Не запускай `prepare`, `fill` или `publish` повторно до выяснения результата.
9. После `result_verified` выполни `npm run vk -- inspect-result --url "<result.url>" --screenshot-all`, визуально проверь созданные в системной временной папке снимки всех вложений и только затем обнови `REPORT.MD`.

Не обновляй страницу вручную ни во время `fill`, ни на экране «Настройки», ни после клика отправки. VK восстанавливает черновик после обновления, поэтому повторный `fill` может начать добавлять те же фотографии поверх сохранённых. Команда `fill` сама использует полностью совпадающий черновик или очищает несовпадающий и собирает форму заново.

Если команда прервалась, зависла внешне или модель потеряла предыдущий JSON-ответ, сначала выполни `npm run vk -- status` и продолжай строго по состоянию:

- `prepared` → `session`, затем `open-group`;
- `group_checked` → `fill --suggested-reviewed`;
- `form_verified` → `publish --token <reviewToken>` из `status`; команда умеет продолжить как с формы «Новый пост», так и с уже открытого экрана «Настройки»;
- `submit_attempted` или `result_unknown` → только `verify`, никогда не обновляй форму и не нажимай кнопку ещё раз;
- `result_verified` → визуальная проверка результата и запись в отчёт.

Одна команда может ждать загрузку VK до нескольких минут. Это не основание обновлять страницу или запускать ту же команду параллельно. Дождись завершения процесса; если процесс действительно завершился ошибкой, используй `status`.

CLI автоматически сверяет предложенные записи со всеми `advertisement.md` активных карточек при `open-group`, повторно перед `fill` и непосредственно перед отправкой. Найденное совпадение запрещено обходить. Автоматическая проверка не заменяет смысловую проверку фотографий, предложенных записей и результата. Флаги `--media-reviewed` и `--suggested-reviewed` разрешено передавать только после реальной проверки.

Если группа заблокирована, недоступна или в ней нет кнопки создания либо предложения записи, пропусти ее. При уверенно подтвержденном состоянии пометь причину и дату проверки рядом с группой в `VkGroups.md`, не удаляя адрес: временные ограничения нужно перепроверять в следующих циклах. Отсутствие ссылки «Предложенные» само по себе не является ошибкой: группа может публиковать записи сразу.

## Работа с формой нового поста

В разных вариантах интерфейса VK форма может открываться через «Предложить пост», напрямую через «Создать» или через «Создать» → «Пост». Используй доступный вариант и продолжай только после появления диалога «Новый пост».

Открытие и заполнение формы выполняет команда `fill`. Если селекторы VK изменились и команда остановилась, исследуй интерфейс и исправь общий код `scripts/lib/vk-browser.js`; не создавай одноразовый скрипт и не переходи к глобальным селекторам.

Ищи редактор и `input[type=file]` только внутри диалога «Новый пост». Не используй глобальный файловый input страницы: он может относиться к альбому сообщества. Если вместо вложения в пост открылось добавление фотографий в альбом, ничего не публикуй, удали или отмени ошибочную загрузку и заново открой пустую форму поста.

Добавляй медиафайлы по одному. После каждого файла дождись, пока число видимых карточек вложений или их кнопок удаления увеличится ровно на один. После последнего файла дай интерфейсу завершить обработку и убедись, что число вложений стабильно и равно числу выбранных файлов. При расхождении не отправляй пост: дождись обработки или пересобери форму.

При автоматической сверке текста нормализуй только переводы строк: приведи `CRLF` и одиночные `CR` к `LF` как в редакторе VK. После этой нормализации текст должен совпадать с `advertisement.md` полностью; не игнорируй другие различия и не обрезай содержимое.

Клик по кнопке загрузки не означает, что файл добавился. Успех загрузки подтверждает только увеличение фактического числа элементов вложений. Клик по «Далее» не означает отправку: затем обычно появляется экран «Настройки», где требуется отдельная кнопка «Опубликовать» или «Предложить».

## Защита от смешивания объявлений

Если нужно разместить несколько животных, полностью закончи и проверь одно животное, прежде чем переходить к следующему. Не держи одновременно открытыми незавершенные формы или черновики разных животных.

При пакетном размещении обновление `REPORT.MD` входит в обязательное завершение работы с текущим животным: сразу после проверки результата запиши отчёт и только затем выполняй `prepare` для следующего животного. Не откладывай и не объединяй записи в отчёт до конца всей серии публикаций.

Для каждого нового объявления начинай с пустой формы без текста и вложений от предыдущего объявления. Непосредственно перед нажатием кнопки отправки обязательно проверь одновременно:

- в форме виден непустой текст именно из `animals/<вид>/<текущее животное>/advertisement.md`, где `<вид>` — `dogs` или `cats`;
- приложены медиафайлы именно текущего животного и только из его папки, а фактическое число готовых вложений совпадает с числом выбранных файлов;
- приложенные медиафайлы соответствуют устойчивым признакам животного из `info.md`;
- имя и описание в тексте соответствуют животному на фотографиях.

Если хотя бы одно условие не выполнено или соответствие нельзя уверенно проверить, не отправляй пост: очисти форму и собери объявление заново из папки текущего животного.

После отправки проверь подтверждение ВКонтакте и, если запись доступна для просмотра, повторно сверь в ней текст и фотографии. Не начинай следующее животное и не отмечай результат успешным в отчете, пока эта проверка не завершена. Если отправлен ошибочный пост, остановись, сообщи пользователю группу и суть ошибки; не отправляй исправленный пост повторно без согласования, чтобы не создать дубль.

Считай результат успешным только если наблюдается одно из двух:

- опубликованная запись открывается по собственной ссылке, а её текст и число/состав медиа проверены;
- предложенная запись видна в разделе предложенных, а её текст и число/состав медиа проверены.

Если после нажатия кнопки результат неясен, сначала проверь ленту и предложенные. Не нажимай кнопку повторно, пока не исключён уже созданный дубль.

CLI записывает `submit_attempted` непосредственно перед единственным кликом. Состояния `submit_attempted` и `result_unknown` навсегда блокируют повторный вызов `publish` для текущего плана. Используй `verify`; при невозможности подтвердить результат остановись и сообщи пользователю.

При проверке предложенной записи не полагайся только на наличие ссылки «Предложенные N» на странице группы: VK может скрыть её. `verify` дополнительно открывает адрес `wall<owner>?suggested=1`. Служебный элемент «Показать ещё» не является частью текста объявления и игнорируется только при послепубликационной сверке.

Размещай объявления только при соблюдении всех условий:

- чередуй животных в одной группе;
- не размещай животных из папки archive;
- не размещай одно животное в одной группе чаще одного раза за 7 дней;
- выдерживай не менее 1,2 дня между любыми нашими объявлениями в одной группе;
- пропускай группу, если в предложенных постах уже есть наше объявление;
- не размещай кошек в группах про собак и наоборот не размещай собак в группах только про кошек;
- пропускай платные группы и группы у которых приписано что надо пропустить.

После каждой успешно опубликованной или предложенной записи сразу добавляй в `REPORT.MD` дату и время по Москве, имя животного, название и ссылку группы, ссылку на запись или раздел предложенных, результат проверки, число вложений и количество потраченных токенов. Если счётчик токенов недоступен, пиши `н/д (счётчик недоступен)`, не выдумывай число. Не отмечай неотправленные или непроверенные объявления как размещенные.
