# Playwright: надёжное размещение во ВКонтакте

Используй эту инструкцию только при браузерном размещении через Playwright. Названия и `data-testid` относятся к текущему интерфейсу VK и служат устойчивыми ориентирами; если интерфейс изменился, опирайся на смысл элемента и наблюдаемый результат.

## 0. Используй общий сеанс и CLI

Основной путь автоматизации находится в `scripts/vk-post.js`. Запускай его через `npm run vk -- ...` по последовательности из `SKILL.md`.

- Не создавай скрипты вида `post_<имя>.js`.
- Не используй `chromium.launch()` или `browser.newContext()` для размещения.
- Не закрывай окно Edge между шагами и не запускай второй экземпляр, если CDP-порт `9222` уже доступен.
- Для продолжения подключайся к существующему браузеру через `chromium.connectOverCDP('http://127.0.0.1:9222')`.
- Не применяй `while (true)`: каждый цикл ожидания обязан иметь ограничение попыток и завершаться ошибкой.
- Не повторяй отправку после состояния `submit_attempted` или `result_unknown`.
- Не вызывай `page.reload()` для восстановления после зависания формы или экрана «Настройки»: VK сохраняет и восстанавливает черновик с уже загруженными вложениями.

Если общий код перестал соответствовать интерфейсу VK, исправляй его и добавляй офлайн-тест, а не обходи проверки разовым скриптом.

## 1. Сначала проверь авторизацию

Сразу после открытия вкладки с VK, до перехода к группе и любых действий с объявлением:

1. Дождись загрузки страницы.
2. Проверь наблюдаемые признаки входа: видны профиль/аватар или меню аккаунта и отсутствует форма либо кнопка входа. Не считай авторизацию подтверждённой только потому, что открылась публичная страница сообщества.
3. Если вход не выполнен или состояние неясно, не переходи к группе, не открывай форму поста и не загружай медиа. Оставь вкладку открытой, передай управление пользователю и попроси его самостоятельно завершить вход.
4. Не читай и не вводи логин, пароль, код подтверждения или CAPTCHA.
5. После возврата управления повторно проверь признаки авторизованного аккаунта в той же вкладке. Продолжай только после явного подтверждения входа интерфейсом VK.

## 2. Подготовь неизменяемый набор данных

До открытия формы зафиксируй:

- `animal`: имя текущего животного;
- `animal_dir`: абсолютный путь к его единственной папке;
- `expected_text`: полное содержимое `advertisement.md`;
- `media_paths`: упорядоченный список абсолютных путей только из `animal_dir`;
- `expected_count`: длину `media_paths`;
- краткие внешние признаки из `info.md`;
- выбранную группу и основание, почему интервалы и тематика соблюдены.

После этого не подменяй отдельные значения данными другого животного. Для нескольких животных полностью заверши одно объявление и закрой его форму до подготовки следующего.

## 3. Проверь страницу группы

1. Убедись по заголовку, что открыта выбранная группа. Авторизация уже должна быть подтверждена на обязательном первом шаге; если VK снова показывает выход из аккаунта, вернись к шагу 1.
2. Найди «Предложенные N», если ссылка существует, и проверь отсутствие нашего активного объявления. Отсутствие ссылки допустимо для групп с прямой публикацией.
3. Открой форму одним из вариантов: «Предложить пост», «Создать» или «Создать» → «Пост».
4. Продолжай только когда появился диалог с заголовком «Новый пост». Все дальнейшие локаторы ограничивай этим диалогом (`posting_modal_box`), чтобы не попасть в загрузчик альбома страницы.

## 4. Добавь медиа и докажи каждую загрузку

Исходный экран может показывать текст «Загрузить с устройства», а после первого файла — кнопку «Фото/Видео» и скрытый `input[type=file]`. Видимая кнопка иногда получает клик, но не открывает системный выбор файла. Область drag-and-drop может быть перекрыта каруселью. Ни клик, ни отсутствие ошибки не доказывают загрузку.

Надёжная последовательность:

1. Для каждого пути отдельно установи ровно один файл в `input[type=file]` внутри диалога. В Playwright допустим `locator('input[type=file]').first().setInputFiles(path)`.
2. Дождись обработки файла.
3. Посчитай элементы `[data-testid="posting_attachment_item"]` внутри диалога. После файла номер `i` число обязано стать `i`.
4. Если число не увеличилось, не переходи к следующему файлу. Повтори действие только после подтверждения, что текущий файл не добавлен.
5. После последнего файла подожди ещё раз и повторно проверь, что число стабильно и равно `expected_count`.

Не используй количество видимых кнопок «Удалить» как единственный счётчик: карусель виртуализирует слайды и может держать в DOM одну такую кнопку при нескольких вложениях.

## 5. Вставь и точно проверь текст

Заполни `[data-testid="posting_base_screen_input_message"]` полным `expected_text`. Перед «Далее» сравни текст редактора с файлом:

1. Приведи `CRLF` и одиночные `CR` к `LF` с обеих сторон.
2. Для `contenteditable` восстанови смысловой текст из текстовых узлов и `<br>`.
3. Последний `<br>` редактора может быть техническим маркером каретки. Исключай только этот подтверждённый DOM-маркер, а не последний символ исходного текста.
4. Не применяй `trim`, не схлопывай пробелы и не меняй регистр. Длины и строки после нормализации должны полностью совпасть.

Одновременно проверь:

- диалог всё ещё называется «Новый пост»;
- текст непустой и содержит имя текущего животного;
- вложений ровно `expected_count`;
- все использованные пути лежат в `animal_dir` и имеют правильный префикс;
- ранее просмотренные медиа соответствуют `info.md`.

При любом расхождении не отправляй пост. Закрой/очисти форму и собери её заново из зафиксированного набора.

## 6. Отправь ровно один раз

1. Нажми «Далее».
2. На экране «Настройки» проверь превью, имя животного и наличие единственной кнопки отправки. Не включай публикацию в историю, если пользователь этого не просил.
3. Нажми «Опубликовать» или «Предложить» один раз.
4. Дождись исчезновения диалога и наблюдаемого результата. Если ответ завис или неясен, ищи новую запись в ленте и в предложенных; не повторяй отправку вслепую.

Команда `publish` должна уметь продолжить с уже открытого экрана «Настройки». На этом экране считай превью по `[data-testid="posting_preview_attachment_item"]`, а не по `posting_attachment_item` с предыдущего экрана. Кнопка предложения в текущем интерфейсе может называться «Предложить пост», а не только «Предложить».

## 7. Проверь созданную запись

Для прямой публикации открой собственную ссылку записи. Для модерации открой её в «Предложенных». Проверь:

- автор/группа и животное правильные;
- число слайдов равно `expected_count`;
- каждый слайд визуально совпадает с соответствующим исходным медиа и признаками из `info.md`;
- весь текст и контактная ссылка присутствуют.

Если ссылка «Предложенные N» не отображается, открой `https://vk.ru/wall<owner-id>?suggested=1` напрямую. При сравнении текста допускается удалить только служебную финальную строку «Показать ещё»; она относится к интерфейсу VK, а не к записи.

VK при отображении поста может схлопывать серии переносов/пробелов, заменять emoji на `<img alt>` и показывать ссылку без `https://`. Для послепубликационной сверки восстанавливай emoji из `alt`, URL из `href` и сравнивай видимый текст с учётом только этих преобразований рендера. Предотправочная сверка редактора при этом остаётся строгой.

Сохрани каноническую ссылку вида `/wall<owner>_<post>` или ссылку на раздел предложенных. Только после этой проверки обнови `REPORT.MD`.

## 8. Безопасные остановки

Остановись без повторной отправки и сообщи пользователю, если:

- обнаружен уже отправленный неправильный или дублирующий пост;
- после клика нельзя установить, создалась ли запись;
- текст или состав медиа после публикации отличаются от подготовленных;
- VK требует действие пользователя: вход, код подтверждения, капчу или оплату;
- невозможно уверенно сопоставить животное на медиа с `info.md`.
